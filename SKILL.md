## Mission
Input = **any new clinical case history** (text, supported files, source link, or case transcript). Output = a **traceable, clinically reviewed, video-ready production package** designed for short-clip models. NEVER assume the case resembles Case #14; that case is only a validation example.

Default: a **120-second Bengali video**, fifteen **8-second clips** (15 × 8 = 120), 16:9 illustrated medical drama, with **patient narrating earlier** and **clinician reasoning later** when the actual source supports that arc. Honor user overrides; check current generator duration/features before choosing 10-second clips. Every dialogue must be timed against recorded audio, not word count alone.

## Safety, facts and source hierarchy — apply before storytelling
1. Extract from the case: demographics, symptoms/time course, consultations in actual order, exam findings, tests, differential, confirmed diagnosis if any, management, outcome, author/source attribution. Produce a `FACT_REGISTER` with categories: `SUPPORTED`, `ATTRIBUTED`, `UNCONFIRMED`, `DRAMATIZED`, `EXCLUDED` and source locator/quote. Do not turn a differential or illustrative diagram into a confirmed finding.
2. Clinical red flags and potentially unsafe misleading statements get a `HOLD_FOR_CLINICIAN_REVIEW` flag; correct only with verified evidence. If exact disease, vessel, imaging findings, treatment, or outcome are unspecified, say so and script as uncertainty. A teaching conclusion may remain conditional. No new test findings, nonexistent doctors, fixed count of consultations, or invented follow-up.
3. Respect confidentiality and consent. If source contains identifiable patient information, de-identify it; generate fictional likenesses unless real likeness and permission are established. Case narrators are dramatized; mark adapted dialogue as dramatized. No claims of clinical advice for a real patient.
4. Preserve technical medical terms accurately and communicate in natural **Bangladeshi Bengali**. Use English terminology in subtitles where clarity helps. Do not prioritize cinematic suspense over diagnostic correctness.
5. If external fact checking is unavailable, explicitly report `NOT_EXTERNALLY_VERIFIED` and hold public release pending qualified medical review. No invented citations or pretend browsing.

## State machine: do this every new case
Read `references/UNIVERSAL_WORKFLOW.md`, `references/SCHEMAS.md`, then `references/CASE_INTAKE_AND_FACTS.md` and `references/DELIVERABLES_AND_TIMING.md`.

**P0 INTAKE / EVIDENCE:** Accept source, establish an ID (`CASE-YYYYMMDD-<slug>` or user-defined). Extract timeline and fact register. Identify critical missing facts, ambiguities and verification status. Do not ask optional questions; use documented defaults. Ask for an indispensable fact only when cannot proceed safely; otherwise label uncertainty and proceed to a bounded educational adaptation.

**P1 SCRIPT:** Write a compact 2-minute Bengali patient→doctor dramaturgy grounded in the actual case trajectory. Each selected-duration clip gets at most one speaker by default. Each clip is an independent production unit with an identified purpose, not merely a long scene sliced at arbitrary points. For patient-history segments, doctor/nurse seen in flashback may be mute. For diagnosis or reasoning segments, the treating clinician may speak. If no plausible definitive answer, do not script a falsely confirmed diagnosis.

If the supplied history cannot support a substantive 120s story, mark `NEEDS_SOURCE_FOR_SUBSTANTIVE_DRAMA / HOLD`; offer a shorter source-bound draft or an explicitly reviewed uncertainty lesson. Do not pad the default runtime with invented clinical progression or present a twelve-row scaffold as a validated complete drama.

**P2 BIBLES (freeze identities before clips):** Create `CAST_BIBLE`, `VOICE_BIBLE`, `LOCATION_BIBLE`, `STYLE_BIBLE`, `PROP_BIBLE`, plus source asset IDs, approval statuses and versions. Use case-specific fictional labels `P01`, `D01`, `HOME01`, `CLINIC01` etc, NOT the names, ages or rooms from Case #14 unless this is Case #14. Main voices must have fixed identity and repeatable source. Same avatar/voice/room/style asset reused wherever present. Different angles and scene locations are allowed; unexplained identity changes aren't.

**P3 SELECTED-PROFILE MANIFEST:** For every clip provide: `clip_id`, timeline `start_s/end_s/duration_s`, `speaking_character_id` (or `NONE`), `voice_id`, `visible_character_ids`, `location_id`, `exact_bangla_dialogue`, `clinical_fact_ids`, `reference_asset_ids`, `action`, `camera`, `audio_target_s`, `voiceover_or_lipsync`, `generator_mode`, `negative_constraints`, `transition`, `status`. Entire timeline must sum to 120s, with no overlaps/gaps. For nondefault durations make a mathematically valid alternate manifest. No 2-minute final promise when total doesn't match.

**P4 AUDIO PREFLIGHT:** Use the same approved voice identity. External audio: record/render each line before video. Native renderer dialogue: if no separate audio can be exported before generation, permit only the explicitly authorized pilot test, record audio timing as untested, and measure actual spoken intervals on the returned pilot before accepting it. Default Flow 8s clip: target spoken audio ≤7.0s; optional Gemini 10s job: target ≤8.5s including natural pauses; actual duration measurement is authoritative. If no audio yet, mark `AUDIO_UNTESTED`, write conservative dialogue, and request a real test before production. Cut dialogue rather than accelerate unnaturally. If native model audio/voice drifts, make silent visuals and place externally produced master audio tracks in editor; acknowledge extra lip-sync work.

**P5 SELECTED-RENDERER PROMPTS:** For each clip include *exact* named asset IDs, visual start reference, actual speaking character, literal Bengali line, mute characters, camera/action, negative requirements, duration, aspect ratio. Refer to `references/PLATFORM_ROUTES.md` and, for Flow, `references/FLOW_PRODUCTION_CONTRACT.md`. Prompt is NOT a tool call and never claims videos were made. No nonexistent variables such as `video_references: ["last_generated_video"]`. Do not claim `@Persona` exists until the user has saved it in the actual Flow character library.

**P6 PILOTS FIRST:** Produce **two pilots**: earliest patient-speech clip and earliest doctor-speech clip, or two representative distinct speaker/location scenes. Ask user to check generated media. Audit identity, 2D-vs-realism, location, clinical illustration, lip-sync, Bangladeshi speech, duration and unexpected text. On FAIL produce an exact, constrained repair prompt; re-audit the *new* file; keep prior FAIL in history. Do not proceed with bulk clips until both pilot QA gates pass. For a new independent renderer/reference route, additionally test a repeat-speaker job from the planned manifest to check between-conversation identity and voice consistency; see GEMINI_INDEPENDENT_CLIPS.md.

**P7 REMAINING CLIPS / ASSEMBLY:** After pilot passes, generate next clip-ready prompts in order; audit each submitted video. Final assembly in Google Flow Scenebuilder or CapCut/DaVinci/FFmpeg (manual unless verified tool control), preserve total runtime and transition budget. Medical accuracy + disclosure + ownership/attribution + caption timing + legibility + voice consistency + music mix checked before publication. Output `FINAL_STATUS: PASS / REPAIR_REQUIRED / HOLD` with evidence and limitations.
